# DFM — `abilityscores` (v1)

## Назначение

Вывести таблицу характеристик (STR/DEX/CON/INT/WIS/CHA) с модификаторами и спасбросками.

---

## Открытие/закрытие

```
::: abilityscores [k=v ...]   ← хвост можно оставить пустым
... (тело с k=v) ...
:::
```

* Контейнер `abilityscores` может содержать **k=v** токены как **на строке открытия**, так и **внутри тела** (в любом
  сочетании).
* «Хвост» на первой строке **считается частью тела**. Парсинг везде одинаковый.

---

## Токены (ключи) и типы

### Базовые способности (целые 1–30)

`str`, `dex`, `con`, `int`, `wis`, `cha`

### Прочие ключи

* `pb` — proficiency bonus (целое). Если не задан → наследуется из ближайшего родителя `statblock`; иначе `0`.
* `saves` — список способностей для проф. спасбросков. Формат: аббревиатуры **без регистра**, разделители —
  запятая/точка с запятой/пробелы.
  Примеры: `saves="STR,CON"`, `saves="dex wis"`, `saves=Str;Cha`
* `title` — заголовок блока (строка). Если есть пробелы — в кавычках.

### Оверрайды (явные значения)

* `mod_str`, `mod_dex`, … — модификатор (знак опционален: `+2`, `-1`, `2`).
* `save_str`, `save_dex`, … — спасбросок (полный override, имеет приоритет над всем).

> Ключи регистронезависимы. Повтор ключа допустим — **последнее значение побеждает**.

### Формат токенов

* Разделители — пробелы и/или переводы строк.
* Строковые значения с пробелами — в `' '` или `" "`.
* Комментарии: от `#` до конца строки игнорируется.

---

## Вычисления

Для каждой характеристики `X`:

* `mod_X = floor((score_X - 10) / 2)`, если `mod_X` не задан.
* `save_X`:

    1. если задан `save_X` — используем его;
    2. иначе `mod_X + pb`, если `X` присутствует в `saves`;
    3. иначе `mod_X`.

> Диапазон score: 1–30. Если значение вне диапазона или нецелое — в dev-режиме выдаётся варнинг; расчёты ведутся по
> введённому числу (без «тихого» исправления).

---

## Наследование `pb`

* Если внутри `abilityscores` `pb` не указан, берётся `pb` с вершины стека родительского `statblock`.
* При отсутствии родителя — `pb = 0`.

## Поведение и диагностика

* Дубликаты ключей: последнее присваивание побеждает.
* Неизвестные ключи: игнорируются; в dev/preview — варнинг.
* Неверные типы (например `pb="abc"`): значение игнорируется; варнинг.
* Пустой блок (`::: abilityscores … :::`) допустим — рендерятся пустые таблицы (для шаблонов).

---

## Примеры

**1) Всё на открывающей строке + тело**

```
::: abilityscores title="Bear Form" pb=3 saves="dex"
str=19 dex=10 con=16 int=2 wis=13 cha=7
:::
```

**2) Всё внутри**

```
::: abilityscores
title="Bear Form"
pb=3
saves="dex wis"
str=19 dex=10 con=16
int=2 wis=13 cha=7
:::
```

**3) Наследуем `pb` из statblock + явные оверрайды**

```
::: statblock pb=2
  ::: abilityscores saves="STR,CON"
  str=13 dex=12 con=12 int=10 wis=11 cha=10
  save_dex=+5   # полный override спасброска
  mod_wis=+2    # override модификатора
  :::
:::
```

Если хочешь — добавлю короткие unit-тест кейсы к спецификации (табличкой «вход → ожидаемый вывод/mod/save»), чтобы
зашить в CI.
