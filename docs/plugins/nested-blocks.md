# DFM: универсальные «двоеточечные» контейнеры (Nested blocks)

## Базовое правило (для **парных** контейнеров)

* **Открытие:** строка `:{N} name [tail]`, где `N ≥ 3`, `name = [A-Za-z0-9_-]+`, `tail` — произвольный «хвост» (например, `k=v`).
* **Закрытие:** строка, состоящая **ровно из N двоеточий** (можно с пробелами по краям), и **ничего больше**.
* **Вложенность:** если внутри контейнера есть другой **парный** контейнер, у него **должно быть больше двоеточий**:
  внешний `:::` → вложенный `::::` → ещё глубже `:::::`, и т.д.
* **Неограниченная глубина:** можно вкладывать сколько угодно уровней.

> Это тот же принцип, что у «заборов» в код-блоках: чтобы не закрыть внешнее, внутри используют более длинный забор.

### Примеры

```md
::: top-level
text…

:::: nested-level-1
more text…

::::: nested-level-2
deepest…
:::::           <!-- закрываем ровно 5 двоеточиями -->

::::             <!-- закрываем ровно 4 двоеточиями -->

:::               <!-- закрываем ровно 3 двоеточиями -->
```

## Однострочные маркеры (непарные)

* Разметка: `:{N} keyword` (где `N ≥ 3`), **без закрывающей строки**.
* В текущем DFM v1 — это: `pagebreak`, `columnbreak`, `columnreset`.
* Они принимаются с любым `N ≥ 3` для единообразия, **не участвуют** во вложенности и **не требуют** закрытия.

Пример:

```md
:::: columnbreak   <!-- однострочный маркер, «длина забора» ни на что не влияет -->
```

# Диспетчеризация (как движок это понимает)

* Любая строка вида `:{N} name …` — это **контейнер-открытие**.
* Если `name` — зарегистрированный **непарный маркер** (`pagebreak/columnbreak/columnreset`) → создать соответствующий токен и перейти к следующей строке.
* Иначе это **парный** контейнер: читать содержимое до строки с **ровно N** двоеточиями (закрытие); внутренние парные контейнеры должны использовать **большее** `N`, поэтому не мешают.
* Неизвестные **парные** контейнеры можно рендерить «по умолчанию» как
  `<div class="dfm-<name>">…</div>` (чтобы контент не потерялся). Известные — отдать их плагинам.

# Применение к нашим блокам

## Парные контейнеры (следуют правилу N↑ внутрь)

* `statblock` — открытие/закрытие по N; в хвосте и «зоне шапки» — `k=v`.
  ПРЕ-пары (AC/HP/Speed/Init) → **до** `abilityscores`.
  ПОСТ-пары (CR/Languages/Senses) → **сразу после первого** `abilityscores`.
  `pb` из шапки пушится в `env` для наследования.
* `abilityscores` — `k=v` на хвосте и/или в теле, как договорено; также с N-заборами.
* `wide` — парный контейнер, растягивается на всю ширину; также с N-заборами.
* Секции `traits`, `actions`, `bonus-actions`, `reactions`, `legendary-actions`, `lair-actions`, `mythic-actions` — парные, одинаковый шаблон секции; тоже с N-заборами.

## Однострочные (N произвольный, закрытия нет)

* `pagebreak`, `columnbreak`, `columnreset` — принимаются как `:{N} keyword` с любым `N ≥ 3`.

# Грамматика (коротко)

```
OpenLine  := ":"{N} S Name (S Tail)? EOL         ; N ≥ 3
Name      := [A-Za-z0-9_-]+
Tail      := .*
CloseLine := S ":"{N} S? EOL                     ; ровно N двоеточий, без имени
VoidLine  := ":"{N} S (pagebreak|columnbreak|columnreset) S* EOL
```

* Для **парных** контейнеров парсер читает до `CloseLine` с **тем же** `N`.
* Внутренние парные контейнеры должны использовать **большее** `N` — это требование синтаксиса для авторов.
* **VoidLine** создаёт токен и **не требует закрытия**.

---

# Поведение при ошибках (dev)

* Если встречен `CloseLine` с `N`, для которого нет открытого контейнера — оставляем строку как обычный абзац и показываем варнинг «Orphan close fence :N».
* Если файл кончился, а последний парный контейнер не закрыт — закрываем его имплицитно и показываем варнинг «Unclosed container `name` (:N)».
* Если внутри встретился парный контейнер с **таким же** `N`, как у внешнего — это нарушает правило; подсказать варнинг «Inner container uses same :N as outer — use longer fence inside (e.g., ::::).»

---

# Памятка авторам

* Стандартно используйте `:::`.
* Как только вкладываете внутрь другой парный контейнер — **увеличьте** количество двоеточий у **внутреннего**:
  `::: outer` → `:::: inner` → `::::: inner2` …
* Однострочные маркеры можно писать с любым количеством двоеточий: `::: columnbreak`, `:::: pagebreak` — неважно.
