# TOC (оглавление) — спецификация и usage

## Зачем

* Пишем **обычный список ссылок** (Markdown `- [Текст](#id)`), без ручных номеров.
* После разбивки на страницы TOC «гидратируется»: справа появляется **номер страницы** из пагинации, а промежуток заполняется **точечными лидерами**.
* Номера берём из атрибута **`data-page-count`** у контейнера страницы **`<section class="page">…`**.

---

## Как писать в Markdown

1. **Добавьте якоря** у заголовков разделов (цели ссылок):

   ```md
   ## Вступление {#intro}
   ## Глава 1 {#ch1}
   ### Сцена 1 {#scene1}
   ```

   > (если используете `markdown-it-attrs`, можно так; иначе — вручную `id` в HTML тегах заголовков.)

2. **Оберните список** в контейнер `toc` и укажите ссылки на эти якоря:

   ```md
   ::: toc
   - [Вступление](#intro)
   - [Глава 1](#ch1)
     - [Сцена 1](#scene1)
   :::
   ```

   > Никаких `::` разделителей и ручных номеров писать **не нужно** — они появятся автоматически.

3. (Опционально) можно передать атрибуты оформления в `{…}`:

   ```md
   ::: toc {span="all"}   <!-- растянуть TOC на всю ширину в двухколоночном блоке -->
   - [Глава 2](#ch2)
   :::
   ```

---

## Как это работает внутри (концепт)

1. MarkdownIt рендерит контейнер `toc` как обычный `<ul><li><a href="#…">…</a></li></ul>`.
   Если подключён универсальный контейнер, он сделает обёртку:

   ```html
   <div class="dfm-container dfm-toc toc" …>
     <div class="dfm-container__body">
       <ul>…</ul>
     </div>
   </div>
   ```

   > Для вас достаточно знать, что есть класс **`.toc`** — именно к нему привязаны стили.

2. Пагинация (`wrapIntoPages`) разбивает документ на:

   ```html
   <section class="page" data-page-count="1">…</section>
   <section class="page" data-page-count="2">…</section>
   …
   ```

3. **Пост-проход (гидратация TOC)** после пагинации:

    * Находит все контейнеры `.toc`.
    * Для каждого `<a href="#target">` ищет `#target` в документе, поднимается до ближайшего `section.page`, читает `data-page-count`.
    * Превращает узел в строку с тремя частями: текст, точки, номер страницы.
      Итоговая разметка одного пункта:

      ```html
      <li>
        <a href="#ch1" class="toc__row">
          <span class="toc__text">Глава 1</span>
          <span class="toc__dots" aria-hidden="true"></span>
          <span class="toc__page">2</span>
        </a>
      </li>
      ```
    * Если цель не найдена — ставит `?` и класс `is-missing`.

4. Универсальный контейнер **не конфликтует**: он уже отработал раньше и просто дал обёртку `.toc`; гидратор работает **после** пагинации и меняет только внутренности списка.

## CSS (точечные лидеры и верстка строки)

Используйте класс `.toc` (без `dfm-`), он всегда будет на корневом контейнере.

```css
/* Сброс стандартных маркеров */
.toc ul { list-style: none; margin: 0; padding: 0; }
.toc li { margin: .2rem 0; }

/* Строка оглавления: три зоны — текст, лидеры, номер страницы */
.toc a, .toc .toc__row {
  display: flex;
  align-items: baseline;
  gap: .5rem;
  text-decoration: none;
  color: inherit;
}

/* Текст (необязательно запрет переноса) */
.toc .toc__text { /* white-space: nowrap; */ }

/* Лидеры: заполняют пространство точками (по базовой линии) */
.toc .toc__dots {
  flex: 1 1 auto;
  border-bottom: 1px dotted currentColor;
  opacity: .6;
  transform: translateY(-.15em);
}

/* Номер страницы справа */
.toc .toc__page { white-space: nowrap; }

/* Вложенность */
.toc ul ul { padding-left: 1.2rem; }

/* Опционально: растягивание TOC на всю ширину в двухколоночных блоках */
.toc[data-span="all"] { column-span: all; -webkit-column-span: all; }

/* Подсветка битых ссылок */
.toc .is-missing .toc__page { opacity: .5; }
```

## Ограничения и оговорки

* Номер берётся из ближайшего предка `section.page[data-page-count]` — то есть уже из результата пагинации.
* Если элемент цели попадает на разрыв, используется страница, где реально находится **его DOM** после разбиения.
* Номер страницы — **строка**: если вы задаёте кастомные пометки (римские, «Appendix A») через механизмы пагинации, TOC возьмёт их как есть.
* Если не нашли `#id`, ставим `?` и класс `is-missing`; это повод проверить якоря.

---

## Короткий пример

Markdown:

```md
::: toc
- [Вступление](#intro)
- [Глава 1](#ch1)
  - [Сцена 1](#scene1)
:::

## Вступление {#intro}
…текст…

## Глава 1 {#ch1}
…текст…

### Сцена 1 {#scene1}
…текст…
```

После пагинации и гидрации TOC пункты получат номера из `<section class="page" data-page-count="…">`.
