# i18n (переводы) — как это работает в DFM

Ниже — короткая, практичная спецификация без лишней магии. Переводы включаются только там, где **явно** помечено ключом.

## Что переводим

Только элементы, у которых есть **`data-i18n-key="..."`**.
Примеры того, что обычно помечают:

* UI-лейблы и заголовки разделов (например, «Actions», «Traits», «AC», «HP», «Mod», «Save», «Contents»).
* Любые подписи, метки и короткие слова интерфейса в ваших плагинах/темах.

> Свободный авторский текст (абзацы, описания, названия комнат и т.п.) **не** переводится автоматически — он остаётся как есть.

## Где живёт словарь

Один файл на язык, без алиасов и фолбэков.

```
src/i18n/ru.json
```

Пример:

```json
{
  "section.actions": "Действия",
  "section.traits": "Черты",
  "label.ac": "КД",
  "label.hp": "ОЗ",
  "label.speed": "Скорость",
  "label.init": "Инициатива",
  "table.mod": "Мод",
  "table.save": "Спас",

  "ability.str": "Сила",
  "ability.dex": "Ловкость",
  "ability.con": "Телосложение",
  "ability.int": "Интеллект",
  "ability.wis": "Мудрость",
  "ability.cha": "Харизма",

  "skill.nature": "Природа",
  "skill.stealth": "Скрытность",
  "skill.athletics": "Атлетика"
}
```

* Если ключа нет — **ничего не меняем** (никаких ошибок и подстановок).
* Формат ключей — на ваше усмотрение, но рекомендуем неймспейсы: `section.*`, `label.*`, `table.*`, `ability.*`, `skill.*`, `ui.*`.

## Как выбирается язык

* Во фронтматтере документа:

  ```yaml
  ---
  lang: ru
  ---
  ```
* На корневом DOM-узле документа выставляется `lang="ru"`.
* Любой контейнер может локально переопределить язык:

  ```md
  ::: sidebar {lang="en"}
  ...контент на английском...
  :::
  ```

  Внутри такого контейнера перевод берётся из `en.json`.

## Как отметить текст для перевода

Отмечайте **носители коротких лейблов** (не большие блоки). Например:

```html
<h4 class="sb-section__title" data-i18n-key="section.actions">Actions</h4>

<dt data-i18n-key="label.ac">AC</dt>
<dt data-i18n-key="label.hp">HP</dt>

<th data-i18n-key="table.mod">Mod</th>
<th data-i18n-key="table.save">Save</th>
```

> Для любых специальных компонентов следуйте той же схеме: видимая подпись → элемент с `data-i18n-key="..."`.

## Когда выполняется перевод

**Один пост-проход по HTML** после рендера Markdown (и до/после пагинации — не критично для текстов). Алгоритм прост:

1. Для каждого элемента с `data-i18n-key` определить язык (по ближайшему предку с `lang`, иначе — язык документа).
2. Взять перевод из `src/i18n/<lang>.json` по ключу.
3. **Заменить текстовое содержимое элемента** на перевод (режим всегда *replace*).
4. Если ключ отсутствует — оставить исходный текст.

## Примеры (до/после)

**Исходный HTML (до i18n):**

```html
<h4 data-i18n-key="section.actions">Actions</h4>
<dt data-i18n-key="label.ac">AC</dt>
<th data-i18n-key="table.mod">Mod</th>
```

**После i18n при `lang: ru`:**

```html
<h4 data-i18n-key="section.actions">Действия</h4>
<dt data-i18n-key="label.ac">КД</dt>
<th data-i18n-key="table.mod">Мод</th>
```

**Локальный язык на контейнере:**

```html
<div class="toc" lang="en">
  <h3 data-i18n-key="ui.contents">Contents</h3>
</div>
```

(Внутри `.toc` берётся словарь `en`, независимо от языка документа.)

## Рекомендации для авторов плагинов/тем

* Не помечайте большие куски контента; размечайте **краткие подписи**.
* Держите ключи стабильными: смена ключа = необходимость правки словарей.
* Старайтесь, чтобы структура DOM не менялась от перевода (только текст внутри).
* Для чисел и значений (например, «… 12») ключ ставьте на **сам лейбл** («Природа», «Сила») — цифры не переводятся.
* Если компоненту нужен составной текст, разбивайте его на части с отдельными ключами.

## Ограничения (намеренные)

* Нет fallback-языков и алиасов.
* Нет режимов замены (`aria/tooltip` и т.п.) — всегда **replace**.
* Перевод не затрагивает ссылки/ID/якоря (если нужно — задавайте их явно).
* Перевод не делает переносы, кавычки и прочую типографику — это вне i18n.
